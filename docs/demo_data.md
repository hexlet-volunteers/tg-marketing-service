# Демо-данные: `seed_demo` и `clear_demo`

Две management-команды наполняют и очищают локальную БД демонстрационными
данными из каталога [`mocks/`](../mocks/):

- `seed_demo` — создаёт или обновляет демо-записи;
- `clear_demo` — удаляет только записи, созданные `seed_demo`.

Команды предназначены для локальной разработки и проверки Inertia-экранов.
На боевой БД их запускать не следует.

## Быстрый старт

```sh
make migrate
make seed-demo
```

Сброс к исходному состоянию:

```sh
make clear-demo
make seed-demo
```

Make-цели — обёртки без аргументов:

```sh
make seed-demo   # uv run python manage.py seed_demo
make clear-demo  # uv run python manage.py clear_demo
```

Флаги `clear_demo` передаются только напрямую через `manage.py`.

## Ограничения запуска

| Команда | `DEBUG=False` | `PROD=t` | Флаги |
|---------|---------------|----------|-------|
| `seed_demo` | `CommandError` | `CommandError` | нет |
| `clear_demo` | `CommandError` | **разрешена** | `--force`, `--keep-roles` |

`seed_demo` работает только при `DEBUG=True` и `PROD != t`.

`clear_demo` по умолчанию тоже требует `DEBUG=True`, но флаг `--force`
снимает это ограничение. Отдельной проверки `PROD` у `clear_demo` нет,
поэтому запускать её в production с `--force` опасно: критерии удаления
описаны ниже.

Обе команды выполняются в `transaction.atomic`: при ошибке изменения
откатываются целиком.

## Что делает `seed_demo`

Команда запускает пайплайн из
[`apps/users/demo/pipeline.py`](../apps/users/demo/pipeline.py) в фиксированном
порядке:

1. роли;
2. пользователи;
3. каналы;
4. модераторы каналов;
5. посты, реакции и разбор поста;
6. статистика каналов;
7. подборки;
8. AI-инсайты;
9. компоненты главной;
10. подписки;
11. статьи блога.

Текущие моки создают:

| Данные | Состав |
|--------|--------|
| Роли | `user`, `guest`, `channel_moderator`, `partner` из `ROLE_LABELS` |
| Пользователи | 4 аккаунта: `demo_admin`, `demo_user`, `demo_partner`, `demo_moderator`; пароль `demo123` |
| Партнёр | профиль `demo_partner` со статусом `active` и балансом `12500.00` |
| Подписки | `demo_user` — Free, `demo_partner` — Pro (год), `demo_moderator` — Pro (месяц), `demo_admin` — Agency (год) |
| Каналы | 10 каналов с `channel_id` от `100001` до `100010` |
| Модераторы | привязки демо-пользователей к каналам (`ChannelModerator`) |
| Посты | по 4 поста на канал; реакции, `PostAnalysis` для первого поста и похожие посты |
| Статистика | по 7 дней на канал (`ChannelStats`) |
| Подборки | 6 групп из `MOCK_COLLECTIONS`; первые две сохранены у `demo_user` |
| AI-инсайты | 4 записи для `demo_user` |
| Главная | 7 компонентов из `LANDING_COMPONENTS` |
| Блог | 4 статьи из `ARTICLES`, автор — `demo_admin`, все опубликованы |
| Тарифы | не создаются и не изменяются; `Plan` приходят из миграций |

`demo_admin` дополнительно получает `is_staff=True` и `is_superuser=True`.
Почта демо-пользователей имеет вид `<username>@demo.test`.

### Учётные записи

| Логин | Пароль | Почта | Роль |
|-------|--------|-------|------|
| `demo_admin` | `demo123` | `demo_admin@demo.test` | `user` + staff/superuser |
| `demo_user` | `demo123` | `demo_user@demo.test` | `user` |
| `demo_partner` | `demo123` | `demo_partner@demo.test` | `partner` |
| `demo_moderator` | `demo123` | `demo_moderator@demo.test` | `channel_moderator` |

### Идемпотентность

Повторный `seed_demo` обновляет существующие демо-записи, а не дублирует их:

- пользователи, каналы, подборки, инсайты, компоненты главной, статьи и
  подписки создаются через `update_or_create`;
- посты обновляются по паре `(channel, telegram_message_id)`, а посты за
  пределами ожидаемого диапазона удаляются;
- реакции пересоздаются для демо-постов;
- статистика демо-каналов удаляется и создаётся заново;
- роли, истории ролей и настройки уведомлений вставляются с
  `ignore_conflicts=True`;
- у демо-подборок удаляются прежние `AutoGroupRule` (новые не создаются).

### Пример вывода

Для текущих моков команда выводит строку вида:

```text
Пользователи: 4 | Каналы: 10 | Посты: 40 | Статистика: 70 | Группы: 6 | Сохранения: 2 | AI-инсайты: 4 | Главная: 7 | Тарифы: 3 | Статьи блога: 4
```

## Что делает `clear_demo`

Команда удаляет демо-данные в порядке, безопасном для внешних ключей:

1. реакции;
2. посты;
3. статистика;
4. модераторы;
5. AI-инсайты;
6. сохранения, правила автоподбора и подборки;
7. статьи блога;
8. компоненты главной;
9. каналы;
10. история ролей и роли (если не указан `--keep-roles`);
11. подписки и пользователи.

### Критерии удаления

| Объект | Что удаляется |
|--------|---------------|
| Пользователи | `username` из `DEMO_USERNAMES` |
| Подписки | подписки демо-пользователей |
| Роли | коды из `ROLE_LABELS`, если на них не осталось активных назначений |
| История ролей | записи демо-пользователей (если не указан `--keep-roles`) |
| Каналы | все `TelegramChannel` с `channel_id >= 100000` |
| Посты, реакции, статистика, модераторы | всё, что связано с каналами из диапазона выше |
| AI-инсайты | записи демо-пользователей или каналов из диапазона |
| Подборки | группы с именами из `MOCK_COLLECTIONS`, а также группы, где владелец или куратор — демо-пользователь |
| Сохранения и `AutoGroupRule` | записи групп с именами из `MOCK_COLLECTIONS` |
| Статьи блога | slug из `ARTICLES` или автор — демо-пользователь |
| Компоненты главной | `component_type` из `LANDING_COMPONENTS` |
| Тарифы | **не удаляются**; в сводке показывается их текущее количество |

`clear_demo` не трогает обычных пользователей, каналы вне диапазона
`channel_id >= 100000`, а также записи, которые не подпадают под критерии
из таблицы выше.

### Флаги

- `--force` — разрешает запуск при `DEBUG=False`. Проверки `PROD` нет.
- `--keep-roles` — оставляет роли и историю ролей демо-пользователей.

Пример запуска с флагами:

```sh
uv run python manage.py clear_demo --force --keep-roles
```

### Пример вывода

Сводка печатается после удаления, поэтому счётчики демо-сущностей равны нулю.
Отдельно выводится число удалённых пользователей:

```text
Пользователи: 0 | Каналы: 0 | Посты: 0 | Статистика: 0 | Группы: 0 | Сохранения: 0 | AI-инсайты: 0 | Главная: 0 | Тарифы: 3 | Статьи блога: 0 | Удалено пользователей: 4
```

## Важные ограничения

- **Диапазон ID.** Всё с `channel_id >= 100000` считается демо-каналом.
  Не запускайте `clear_demo` на БД, где могут быть реальные каналы с такими
  ID.
- **Списки из моков.** Очистка опирается на текущие `DEMO_USERNAMES`, имена
  подборок, slug статей и типы компонентов. Если переименовать запись в
  `mocks/`, старая демо-запись может остаться в БД.
- **Тарифы.** `Plan` создаются миграцией и командами не изменяются.
- **Production.** `seed_demo` в production заблокирована.
  `clear_demo --force` технически может запуститься, но из-за широких
  критериев удаления не предназначена для боевой БД.
