# Контракт регистрации

## Эндпоинт

`GET /auth/create/` возвращает Inertia-компонент `FormRegistration`.

`POST /auth/create/` создаёт пользователя по email.

## Поля запроса

Обязательные поля:

- `email`
- `password1`
- `password2`
- `terms` — обязательное согласие на обработку персональных данных;
  например, `terms=on` для HTML-формы. Отсутствующее или ложное значение
  возвращает ошибку поля `terms`, пользователь не создаётся.

Необязательные поля:

- `first_name`
- `last_name`
- `username`
- `bio`
- `avatar_image`

Форма принимает необязательный `username` и использует переданное непустое
значение после удаления пробелов по краям. Только если поле отсутствует или
пустое, сервер генерирует имя из части email до `@` и случайного суффикса.
`username` не входит в возвращаемый `form.data`.

## Успешная регистрация

Если данные валидны, сервер:

- создаёт пользователя;
- фиксирует согласие на обработку ПДн с актуальной версией документа;
- назначает `role="user"`;
- `avatar_image` принимает только HTTP(S)-URL длиной не более 2048 символов;
- если `avatar_image` не передан, назначает дефолтный аватар из статического
  файла `/static/users/default-avatar.svg`, сохраняя абсолютный HTTP(S)-URL
  с протоколом и хостом текущего запроса;
- выполняет вход нового пользователя через Django auth;
- редиректит на дашборд: `homepage:dashboard` (`/dashboard/`).

## Ошибки валидации

Если данные невалидны, сервер снова рендерит `FormRegistration` и передаёт данные формы вместе с ошибками:

```json
{
  "form": {
    "data": {
      "first_name": "",
      "last_name": "",
      "password1": "",
      "password2": "",
      "email": "",
      "bio": "",
      "avatar_image": "",
      "terms": ""
    },
    "errors": {}
  }
}
```

Уникальность email возвращается как ошибка поля `email`.

Для GET все значения `form.data` пустые. При ошибке POST `terms` содержит
переданное строковое значение (например, `"on"`) или `""`, если поле отсутствовало.

Ошибки валидаторов пароля Django возвращаются как ошибки поля `password2`.

Значения `password1` и `password2` не возвращаются клиенту после ошибки: в `form.data` они всегда пустые.
